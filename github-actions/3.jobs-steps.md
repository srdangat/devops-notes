# GitHub Actions: Jobs, Steps, Dependencies

---


A **workflow** is made of **jobs**, and each job is a sequence of **steps**. Understanding this hierarchy is crucial for building reliable pipelines:

- **Workflow**: defines triggers and jobs.  
- **Job**: a unit of work that runs on a **runner**. Jobs can run **in parallel or sequentially**.  
- **Step**: a single task executed as part of a job. Steps can run shell commands (`run`) or actions (`uses`).

---

## 1. Jobs

- Jobs run on a **specific runner** and contain multiple steps.
- Example:

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - run: echo "Hello"
```

---

## 2. Steps

- Steps are **executed sequentially** inside a job.
- They can be:
  - **Actions**: reusable scripts (`uses`)
  - **Commands**: run shell commands (`run`)
- Example:

```yaml
steps:
  - name: Checkout code
    uses: actions/checkout@v4

  - name: Install dependencies
    run: npm install

  - name: Run tests
    run: npm test
```

---

## 3. Job Dependencies

- Jobs **run in parallel by default**.
- Use `needs:` to specify **job dependencies**:

```yaml
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - run: echo "Running tests"

  deploy:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - run: echo "Deploying"
```

- Ensures **`deploy` runs only after `test` completes successfully**.
