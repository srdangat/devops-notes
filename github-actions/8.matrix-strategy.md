# GitHub Actions: Matrix Strategy

---

A **matrix strategy** allows you to run the **same job multiple times in parallel** with different configurations. This is ideal for testing across multiple OS environments, language versions, or any combination of variables.

---

## 1. Basic Matrix

- Define a `matrix` under `strategy` with one or more variables.
- GitHub creates **one job per combination** automatically.

```yaml
jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node-version: [16, 18, 20]    # Runs 3 parallel jobs

    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}    # Access matrix value

      - name: Run tests
        run: npm test
```

---

## 2. Multi-dimensional Matrix

- Combine multiple variables — GitHub runs **every combination**.
- Example: 2 OS × 3 Node versions = **6 parallel jobs**.

```yaml
jobs:
  test:
    strategy:
      matrix:
        os: [ubuntu-latest, windows-latest]
        node-version: [16, 18, 20]

    runs-on: ${{ matrix.os }}    # Use matrix value for runner

    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}

      - name: Run tests
        run: npm test
```

---

## 3. Excluding Specific Combinations

- Use `exclude:` to **skip certain combinations** you don't need.

```yaml
strategy:
  matrix:
    os: [ubuntu-latest, windows-latest, macos-latest]
    node-version: [16, 18, 20]
    exclude:
      - os: windows-latest
        node-version: 16    # Skip Node 16 on Windows only
```

---

## 4. Including Extra Combinations

- Use `include:` to **add specific combinations** or **attach extra variables** to existing ones.

```yaml
strategy:
  matrix:
    os: [ubuntu-latest, windows-latest]
    node-version: [18, 20]
    include:
      - os: ubuntu-latest
        node-version: 20
        experimental: true    # Extra variable only for this combo
```

---

## 5. `fail-fast` and `max-parallel`

- **`fail-fast`** (default: `true`): cancels all remaining jobs if one fails.
  - Set to `false` to let all jobs complete even if one fails.
- **`max-parallel`**: limits how many jobs run at the same time.

```yaml
strategy:
  fail-fast: false       # Don't cancel others on failure
  max-parallel: 2        # Run at most 2 jobs at a time
  matrix:
    node-version: [16, 18, 20]
```

---

## Key Rules

- Matrix values are accessed via `${{ matrix.VARIABLE_NAME }}`.
- Each matrix combination runs as a **completely independent job** with its own runner.
- Use `fail-fast: false` when you want **full test coverage** across all combinations regardless of failures.
- Matrix jobs count against your **concurrent job limits** — use `max-parallel` to control this.
- Matrices are ideal for: **cross-platform testing**, **multi-version compatibility**, and **multi-environment deploys**.
